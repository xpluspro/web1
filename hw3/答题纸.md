# 互联网应用开发技术 - 作业3 答题纸

## 一、作业完成说明

本次作业在作业1静态书店项目的基础上进行了 React 化重构。重构后的项目使用 React 和 React Router 组织页面，使用统一的数据文件管理图书信息，并通过函数组件拆分公共页面结构和业务模块，使工程更符合构件式开发思想，也更方便后续迭代扩展。

当前项目已经完成以下核心功能：

1. 能够正常展示书籍列表页。
2. 能够根据点击的具体图书跳转到对应详情页。
3. 书籍详情页展示的数据与列表页中的图书保持一致。
4. 图书数据统一保存在前端数据文件中，不再分散在多个 HTML 页面里。
5. 项目整体改造成 React 单页应用，并保留了购物车、下单和支付成功等后续扩展页面。

## 二、如何遵循 React 构件式开发原则

### 1. 先拆布局，再拆业务

原项目中页头、页脚、书籍卡片、价格筛选区、详情页结构、购物车数量控制等内容在多个页面里重复出现。重构时先把这些重复结构抽成可复用组件，再让页面组件负责组合它们，而不是继续把大段 HTML 分散在不同页面文件中。

例如：

- `AppLayout.jsx` 负责统一的整体布局。
- `SiteHeader.jsx` 和 `SiteFooter.jsx` 负责全站公共框架。
- `BookCard.jsx` 负责单本图书的展示。
- `PriceFilterSidebar.jsx` 负责价格筛选区域。
- `QuantityStepper.jsx` 负责数量增减控件。
- `OrderSummary.jsx` 负责购物车和订单页共用的金额摘要模块。

这种拆分方式遵循了“单一职责”思想，每个组件只关心自己的一小块界面和行为，使代码更容易维护和复用。

### 2. 页面由组件组合而成

页面层不再直接写完整的大型页面结构，而是由多个组件进行组合：

- `BookListPage.jsx` 由推荐区、筛选区和书卡列表组成。
- `BookDetailPage.jsx` 由图书信息区、简介区、数量控制区和推荐阅读区组成。
- `CartPage.jsx` 和 `OrderPage.jsx` 共用订单摘要和数量调节等组件。

这样做的好处是：

- 页面逻辑更清晰。
- 改动某一块内容时不会影响整页。
- 后续新增页面时可以直接复用已有组件。

### 3. 使用 Props 传递数据和行为

组件之间通过 `props` 通信，而不是依赖全局 DOM 查询或硬编码链接。

例如：

- `App.jsx` 将书籍数据、购物车数量、搜索词和筛选条件传给各个页面组件。
- `BookListPage.jsx` 将单本图书对象传给 `BookCard.jsx`。
- `BookDetailPage.jsx` 接收来自 `App.jsx` 的 `onAddToCart` 方法，在点击“加入购物车”时把图书和数量回传给上层。

通过这种方式，组件边界清晰，数据来源明确，符合 React 自上而下的数据流设计。

### 4. 使用 State 管理可变界面状态

本项目中所有会变化的数据都改成由 React `state` 管理，而不是像原项目那样手动操作 DOM：

- 书籍搜索词使用 `state` 保存。
- 价格筛选条件使用 `state` 保存。
- 详情页中的购买数量使用 `state` 保存。
- 购物车列表使用 `state` 保存。
- 下单成功提示和最近一次订单信息也由 `state` 管理。

这样做可以保证“数据变化，界面自动更新”，提高代码可靠性和可读性。

## 三、工程结构组织方案

### 1. 按职责分目录

重构后工程按“页面、组件、数据、工具函数”划分目录：

- `src/pages/`：页面级组件。
- `src/components/`：可复用组件。
- `src/data/`：静态业务数据。
- `src/lib/`：工具函数和本地存储逻辑。

这种目录结构比“所有文件堆在根目录”更清晰，后续查找和扩展都更方便。

### 2. 路由统一管理页面跳转

原项目通过 `details1.html`、`details2.html` 等多个静态页面跳转。重构后统一改为 React Router 路由：

- `/`：书籍列表页
- `/books/:slug`：图书详情页
- `/cart`：购物车页
- `/order`：订单确认页
- `/success`：支付成功页
- `/login`：登录页

其中详情页使用动态路由参数来区分具体图书，不再需要为每本书单独创建一个 HTML 文件，工程结构更简洁。

### 3. 数据集中管理

原项目中的书名、作者、价格、图片等信息分散在首页和多个详情页中，存在大量重复。重构后把图书数据统一写在 `src/data/books.js` 中，字段包括：

- `id`
- `slug`
- `title`
- `author`
- `category`
- `price`
- `cover`
- `summary`
- `description`
- `highlights`

这样可以保证：

- 列表页和详情页始终使用同一份数据。
- 修改一本书的信息时只需要改一处。
- 更符合前端数据驱动渲染的思想。

### 4. 本地持久化逻辑独立封装

购物车逻辑被抽到 `src/lib/cartStorage.js` 中，用来处理：

- 读取购物车
- 写入购物车
- 增加商品
- 修改数量
- 删除商品
- 计算订单摘要

页面组件只负责调用这些函数和展示界面，而不直接处理底层存储细节，提高了可维护性。

## 四、如何满足题目中的关键要求

### 1. 使用 React 和 React Router 重构页面

项目入口改为 `src/main.jsx`，通过 `BrowserRouter` 管理路由；原来的多页面静态站点已经重构为 React 单页应用。

### 2. 实现书籍列表页到书籍详情页的跳转

在列表页点击某本书后，会跳转到 `/books/:slug` 对应的动态详情页，并展示当前图书的完整信息。

### 3. 页面跳转时保持数据关联

数据关联通过以下方式保证：

- 书籍列表和详情页共用 `src/data/books.js` 中的同一份数据。
- 列表页通过 `Link` 携带页面状态，并由详情页结合路由参数定位当前图书。
- 页面组件和子组件之间通过 `props` 传递数据和操作函数。
- 搜索词、筛选条件、购物车等动态信息通过 React `state` 维护。

因此能够保证点击哪本书，就进入哪本书的详情页，不会出现数据错乱。

### 4. 所有数据写在前端文件中

所有图书基础数据统一保存在 `src/data/books.js` 中，前端直接读取并渲染，不依赖后端接口。

### 5. 体现 React 构件化设计思想

项目没有继续沿用“一个页面一个大文件”的静态开发方式，而是把公共布局、通用控件、业务模块和页面拆分成多个函数组件，并通过组合来构建页面。

### 6. 工程结构合理、可维护性强

工程结构按职责划分，数据、页面、组件、工具函数互相分离；动态路由替代了重复页面；购物车逻辑统一封装；后续如果需要新增书籍、增加分类或继续扩展订单功能，改动范围都比较小。

## 五、与原项目相比的主要改进

1. 由多页面静态工程升级为 React 单页应用。
2. 删除了 4 个重复详情页，改成单一动态详情页。
3. 删除了依赖 DOM 手动操作的旧页面脚本，改成 React 状态驱动渲染。
4. 将书籍数据从 HTML 中抽离到统一数据文件。
5. 将购物车和订单流程整理到统一的数据流中。
6. 工程目录更清晰，更便于后续迭代1继续扩展。

## 七、总结

本次重构的重点不是只把页面“翻译成 JSX”，而是重新组织整个前端工程：用统一数据源替代重复 HTML，用组件组合替代大段页面复制，用 React `state` 和 `props` 替代手动 DOM 操作，用路由替代分散的静态页面跳转。这样既满足了本次作业要求，也为后续迭代开发打下了更好的基础。
