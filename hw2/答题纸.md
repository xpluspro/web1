### 2. 原始计算器实现分析
- 原始“计算器”页面主要集中在一个 `index.jsx` 文件中，按钮构件、样式常量、状态、运算逻辑和 JSX 渲染都写在同一个模块里。
- 原实现通过 `input / result / operator` 三个状态完成顺序二元运算，适合 `2 + 3 × 4` 这种逐步点击场景，但本质上并没有把整个表达式建模为可解析结构。
- 原实现支持 `+ - × ÷ . % +/-` 等基础操作，但不支持括号，因此无法正确处理 `5×(2+3)` 这类带优先级变化的表达式。

## 二、规划方案

### 1. 模块化拆分
- `CalculatorPage` 作为页面级父组件，负责组合子构件。
- `DisplayPanel` 专注显示历史表达式、当前表达式和预览结果。
- `Keypad` 负责根据按钮配置渲染键盘布局。
- `CalcButton` 作为最小按钮构件，保证构件职责单一。
- `useCalculator` 负责状态管理和交互逻辑。
- `expressionParser` 负责词法分析、AST 构建和表达式求值。
- `expressionInput` 负责输入规则，例如小数点、括号、百分号、退格和正负号切换。

### 2. State 与 Prop 设计
- 父层 Hook `useCalculator` 统一维护 `expression`、`history`、`preview`、`error`。
- `DisplayPanel` 只通过 `props` 接收展示数据，不直接修改状态。
- `Keypad` 和 `CalcButton` 只通过 `props` 接收按钮配置和点击回调，保持函数式开发风格。

### 3. 括号支持方案
- 先将输入字符串分词，得到数字、运算符、括号、百分号等 Token。
- 使用递归下降分析法构建 AST。
- 使用优先级规则处理 `+ - * /`，用分组节点处理括号，用一元节点处理正负号，用后缀节点处理 `%`。
- 最后对 AST 递归求值，得到表达式结果。

### 4. 运行入口兼容方案
- 初版工程使用 Vite 默认入口，直接双击 `index.html` 时会因为 `/src/main.jsx` 属于开发服务器路径而显示空白。
- 为解决这个问题，保留 React 源码与 Vite 工程的同时，额外生成 `standalone/app.js` 与 `standalone/app.css`。
- 当用户直接以 `file://` 方式打开 `index.html` 时，页面会自动加载这套独立 bundle，从而确保浏览器直接打开也能显示计算器界面。
